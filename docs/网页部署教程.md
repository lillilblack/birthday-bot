# 网页版生日名单部署教程（方案 2，2026-08-19）

> 结论先行：**iLink 微信 bot 是「个人机器人」，全队没法都进同一个 bot 查生日**（见 [多用户接入调研结论.md](多用户接入调研结论.md)）。所以另做了一个**纯只读静态网页**放名单，挂 GitHub Pages（免费，仓库已公开），把链接发队群即可——全队都能看「今天/明天谁生日」「接下来要过谁的生日」，也能按名字搜索。

## 1. 网页地址

`https://lillilblack.github.io/birthday-bot/`

## 2. 网页有什么

- 顶部「今天 / 明天」两块：谁生日（没有则显示「今天没有队友生日」）
- 「接下来要过的生日」：未来 12 个，农历生日自动换算成对应公历日期并标「（明年）」
- 「找队员」搜索框：按姓名或姓氏实时过滤
- 「完整名单」：阳历按 1~12 月分组，农历生日单列在最下面（显示「农历 二月廿八」这种），今天/明天的人有角标

## 3. 文件在哪

全部在 `docs/` 目录（GitHub Pages 发布的就是这个目录）：

| 文件 | 作用 |
|---|---|
| `docs/index.html` | 页面本体（CSS / JS 内联，无任何外部 CDN 依赖） |
| `docs/lunar.mjs` | 农历换算库，从 `node_modules/lunar-typescript/dist/index.mjs` 拷贝，和 bot 同一套、结果保证一致 |
| `docs/roster.json` | 网页版名单数据（当前 58 人：阳历 51 + 农历 7） |

> ⚠️ **为什么叫 `roster.json` 而不是 `birthdays.json`**：`.gitignore` 里的 `birthdays.json`（裸文件名）会忽略任意目录下的同名文件，放 `docs/birthdays.json` 会推不上去，所以改名为 `roster.json`。

## 4. 怎么开 Pages（只做一次）

1. 打开 `https://github.com/lillilblack/birthday-bot/settings/pages`
2. **Build and deployment → Source** 选 **Deploy from a branch**
3. **Branch** 选 **`main`** + **`/docs`**
4. **Save**，等约 1 分钟，顶部出现绿框 `Your site is live at ...` 即可访问

## 5. 改名单后怎么同步（重要）

网页是**纯静态、纯只读**，读的是仓库里提交好的 `docs/roster.json`，**不会自动跟着 bot 变**：

- bot 的 `birthdays.json`（或微信自助增改 → `.runtime/birthdays-overlay.json`）改了之后，网页不会自动更新。
- 需要手动把变化同步进 `docs/roster.json`，然后提交推送：

  ```bash
  git add docs/roster.json
  git commit -m "同步网页名单"
  git push
  ```

- overlay 里测试用的「测试员」（m059）已从网页名单中排除。

## 6. 已知坑

- **国内访问**：GitHub Pages 在国内可能时快时慢，队友打不开是 GitHub 网络问题（和 Actions 连微信慢同源），不是网页本身问题，换网络或稍后再试。
- **纯只读**：网页没有「自助增改」入口（GitHub Pages 无后端，写不回名单）。增改生日继续走微信 bot 指令，或改 `birthdays.json` 后同步到 `roster.json`。
