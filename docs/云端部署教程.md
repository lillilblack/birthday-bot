# 生日机器人 · 云端部署教程（电脑关机也能用）

> 目标：把机器人搬到 GitHub 的免费服务器上，让你关机、断网、笔记本合盖，它都照常发生日提醒、照常回微信消息。

---

## 0. 先搞懂原理（30 秒）

**现在的状态**：机器人跑在你自己的 Windows 电脑上（任务计划每分钟调用 `bun run check`），电脑一关机就停了。

**云端之后**：代码推到 GitHub，用 **GitHub Actions**（GitHub 自带的免费定时任务功能）在它自己的服务器上定时跑命令：

| 任务 | 云端什么时候跑 | 对应你本地的哪个命令 |
|---|---|---|
| 回微信消息 | 每 5 分钟 | `bun run check` |
| 发每日生日提醒 | 每天 00:00 | `bun run start` |
| 提醒你「续命」 | 每 6 小时 | `bun run check-expiry` |

你电脑开不开机，跟它毫无关系了。

---

## 1. 动手前，4 个必须知道（诚实版）

这些不是 bug，是这套免费方案的边界，先知道省得后面困惑：

1. **回复不是秒回**。云端定时任务最频繁 5 分钟跑一次，而且 GitHub 是「尽力而为」，实际可能延迟几分钟到十几分钟。发消息后等 5~10 分钟是正常的。
2. **token 会过期（约 24 小时）**。微信这个协议只有「你主动给机器人发消息」时 token 才会刷新。所以你要**每隔一两天给机器人随便发一句**（比如「在吗」），否则它 24 小时后会「断气」收不到也发不出。我们配了个「每 6 小时提醒你续命」的任务，收到「回我一句续命」就回一句即可。
3. **免费额度有上限**。私有仓库每月 2000 分钟免费；公开仓库不限分钟、但代码（不含密钥和名单）会公开。第 2 步教你选。
4. **云服务器在国外**。微信这个 iLink 协议认不认国外 IP，**需要实测**。第 5 步的「手动测试」就是验这一条。如果测试失败，把日志发我，我帮你换方案（比如租台便宜的国内云服务器）。

## 2. 第一步：注册 GitHub + 新建仓库

1. 打开 https://github.com ，注册一个账号（已有就登录）。
2. 登录后，点右上角头像旁边的 **`+`** → **New repository**。
3. 填表：
   - **Repository name**：`birthday-bot`
   - **Public / Private**（下面细说，先往下看）
   - **Initialize this repository with**：**什么都别勾**（不要 README、不要 .gitignore、不要 license）
4. 点绿色 **Create repository**。

**公开 vs 私有，怎么选？**

| | 私有 Private（推荐） | 公开 Public |
|---|---|---|
| 代码是否公开 | 只有你能看 | 全世界能看 |
| 生日名单是否公开 | 不公开（在 Secret 里） | 不公开（在 Secret 里） |
| 密钥是否公开 | 不公开 | 不公开 |
| 免费分钟 | 2000 分钟/月 | 不限分钟 |
| 回消息频率 | 建议 15~30 分钟一次，否则会超 | 可 5 分钟一次 |

**建议**：先选 **Private** 试通，如果觉得回复太慢、想加快，再回来改成 Public 或者我帮你换方案。代码里只有文案和接口调用逻辑，没有秘密，就算公开也不泄露名单和密钥。

---

## 3. 第二步：把项目推上去

在 Windows 上按 **`Win + R`**，输入 `cmd`，回车，打开黑色命令行窗口。

逐行复制下面命令，**把 `你的用户名` 换成你的 GitHub 用户名**，粘贴后回车（每行一次）：

```bat
cd /d "e:\大学\大学生活\辩论队\birthday-bot-master"
git config --global user.email "你的邮箱@example.com"
git config --global user.name "你的用户名"
git remote add origin https://github.com/你的用户名/birthday-bot.git
git branch -M main
git push -u origin main
```

执行最后一条 `git push` 时，会弹窗或命令行让你登录 GitHub：

- 用户名：填你的 GitHub 用户名。
- 密码：**不能填登录密码**，要填一个「Personal Access Token（个人访问令牌）」。怎么生成见 [附录 A](#附录-a--github-推送登录用-pat-令牌怎么弄)。

看到类似 `Writing objects: 100% ... done` 就算成功。刷新浏览器里的仓库页面，能看到文件列表（src、.github、package.json 等）就说明推上去了。

> 注意：`.env` 和 `birthdays.json` 被 `.gitignore` 挡着，**不会**被推上去（这是好事，密钥不上传）。它们会通过第 4 步的「Secrets」交给云端。

---

## 4. 第三步：配置 4 个密钥（Secrets）

密钥就是把 `.env` 里的敏感内容，安全地放进 GitHub，云端跑任务时自动读取。

1. 仓库页面顶部点 **Settings**。
2. 左侧菜单点 **Secrets and variables** → **Actions**。
3. 点绿色 **New repository secret**，逐个添加下面 4 个（名字必须一字不差，包括大小写和下划线）：

| Secret 名字 | 值从哪复制 |
|---|---|
| `ILINK_TOKEN` | 打开 `.env`，复制 `ILINK_TOKEN=` 后面那一整串 |
| `TO_USER_ID` | 复制 `.env` 里 `TO_USER_ID=` 后面那一整串 |
| `CONTEXT_TOKEN` | 复制 `.env` 里 `CONTEXT_TOKEN=` 后面那一整串 |
| `BIRTHDAYS_JSON` | 打开 `birthdays.json`，**Ctrl+A 全选**，复制整个文件内容 |

**BIRTHDAYS_JSON 特别说明**：这是整个 `birthdays.json` 文件内容（从第一个 `[` 到最后一个 `]`），直接整个粘进 Secret 的 value 框即可，GitHub 装得下。

以后**改生日名单**要改两个地方：本地 `birthdays.json` + 这个 `BIRTHDAYS_JSON` Secret。

---

## 5. 第四步：确认云端任务文件已就位

我已经帮你准备好三个云端任务文件，它们会随第 3 步的 push 一起上去：

- `.github/workflows/birthday.yml` —— 每天 00:00 发提醒（今天 + 明天的生日）
- `.github/workflows/check.yml` —— 每 5 分钟轮询回复（**新加**，这是之前云端缺的一块）
- `.github/workflows/expiry-reminder.yml` —— 每 6 小时提醒续命（已有）

你不需要手动改它们，push 成功即可。

**可选**：如果你选了私有仓库、想省分钟，把 `check.yml` 里这一行：

```yaml
    - cron: "*/5 * * * *"
```

改成 `"*/15 * * * *"`（15 分钟）或 `"*/30 * * * *"`（30 分钟），改完再 push 一次。GitHub 网页上就能改（点进文件 → 铅笔图标编辑 → Commit）。

---

## 6. 第五步：手动测试一次（最关键的一步）

这一步验证「云端能不能真的把消息发到微信」，必须做：

1. 仓库页面顶部点 **Actions** 标签页。
2. 左侧列表点 **Reply Check**。
3. 右侧看到 **Run workflow** 按钮 → 点它 → 再点绿色 **Run workflow** 确认。
4. 等那个任务跑完，图标变成**绿色对勾**（约 1 分钟）。
5. 拿出手机，用绑定的微信给机器人发一句 **「你好」**。
6. 等 5~10 分钟，看机器人有没有回。

**结果判断**：

- ✅ **回复了** → 云端打通！现在可以放心关机，机器人在云端自己跑。
- ❌ **没回复** → 点进那次运行（绿色对勾旁边点进去）→ 展开 **Check and reply** 步骤，把里面的红字日志截图发我。最常见原因是「国外 IP 不被微信协议认可」，我来帮你判断下一步。

---

## 7. 第六步：日常使用 & 收尾

- **现在起可以关机了**，机器人靠云端跑。
- **续命**：每隔一两天给机器人发一句消息。收到「回我一句续命」就随手回一句，token 就不会断。
- **看运行记录**：仓库 → Actions，能看到它每次跑的日志和是否成功。
- **改生日名单**：本地改 `birthdays.json` → 同步更新 `BIRTHDAYS_JSON` Secret（第 4 步）。
- **60 天不提交会停**：GitHub 会在仓库 60 天没有任何提交（commit/push）后，自动停掉定时任务。偶尔改点东西 push 一下（比如更新名单）就能续上；就算停了，去 Actions 里点一下也能重新启用。

## 8. 进阶：嫌回复慢想「秒回」

GitHub Actions 是「定时批量跑」，天生做不到秒回。想要秒回，得换成一台**一直开机的服务器**常驻跑 `bun run listen`（每 2 秒轮询）：

- 阿里云 / 腾讯云轻量应用服务器，几十块/年，选「国内地域」（避免国外 IP 问题）。
- 服务器上装 Bun，把项目传上去，后台跑 `bun run listen` 即可。

## 附录 A · GitHub 推送登录用 PAT 令牌怎么弄

现在 GitHub 不允许用登录密码推送代码，要用一个「令牌」当密码：

1. GitHub 右上角头像 → **Settings**。
2. 左侧最下面 **Developer settings** → **Personal access tokens** → **Tokens (classic)**。
3. **Generate new token (classic)**。
4. Note 随便填（如 `birthday-bot`）；Expiration 选长一点（如 90 天）；勾选 **repo** 这一项。
5. 拉到最下 **Generate token**。
6. 复制生成的那串 `ghp_...`（只显示一次，别关掉页面）。
7. 回到命令行 `git push` 登录时，**密码栏粘贴这串 token**（不是你的登录密码）。

以后每次 push 都要用它，记不住就再生成一个。

## 附录 B · 怎么改 check 的频率

1. 仓库里点进 `.github/workflows/check.yml` 文件。
2. 点右上角铅笔图标（Edit this file）。
3. 找到 `- cron: "*/5 * * * *"` 这一行，改成想要的：
   - 每 15 分钟：`*/15 * * * *`
   - 每 30 分钟：`*/30 * * * *`
   - 每 1 小时：`0 * * * *`
4. 点绿色 **Commit changes**。
