# 多用户接入调研结论（2026-08-19）

> 结论先行：**iLink 的微信 bot 本质是「个人机器人」，一个 bot 绑定一个微信用户。想要「一个二维码、全队人人扫、进同一个 bot、消息互相隔离」这个目标，在 iLink 平台上实现不了。**

---

## 1. 诉求

希望机器人只有一个固定二维码，队里每个人都能扫、扫完都能和同一个 bot 对话，但各自发的消息互不影响。

## 2. 结论：做不到，原因有三

（依据腾讯官方 SDK `@tencent-weixin/openclaw-weixin` 源码 + 实测）

1. **二维码是「登录/绑定」码，不是「加好友」码。**
   官方源码 `src/auth/login-qr.ts`：`get_bot_qrcode?bot_type=3` 生成二维码 → 扫码 → `get_qrcode_status` 返回 `bot_token` + `ilink_user_id`（**扫码那个人的 ID**）。即扫一次 = 新建一个 bot，并绑定给扫码的这一个人。

2. **每个 bot 账号只绑定一个微信用户。**
   官方源码 `src/auth/accounts.ts` 里，每个账号只存「一个 token + 一个 `userId`（扫码人）」，没有「多个用户」字段。

3. **微信里没有 bot 的分享入口。**
   实测：绑定的 bot 在微信里不能像普通联系人那样「推荐名片 / 分享二维码」，所以别人没有入口加到你的 bot。

结论：iLink 是「一人一 bot」的个人助手模型，不是「一个 bot 服务一群人」的群机器人模型。

## 3. 一个好消息：隔离代码本身没错

本项目 `src/ilink.ts` 里写的多用户隔离逻辑，和官方 SDK 是一致的——官方 `src/messaging/inbound.ts` 里就是按「账号 + 用户」隔离 context_token：

```ts
function contextTokenKey(accountId: string, userId: string) {
  return `${accountId}:${userId}`; // 按“账号+用户”隔离
}
```

也就是说：**同一个 bot 在 API 层面确实能收到多个人的消息、并按 `from_user_id` 隔离**（本项目 `users` 表正是这个实现）。问题只在于——「多个人根本没有入口加到你的 bot」，所以这套多用户逻辑在 iLink 上永远跑不起来。代码留着无害（单用户时正常降级），只是「多人扫码加入」这个目标实现不了。

## 4. 现实的三条路

| 方案 | 说明 | 评价 |
|---|---|---|
| 1. 保持单用户 | 机器人只有 owner 一个人用，owner 查、owner 自助增改 | 最稳，iLink 原生形态 |
| 2. 绕开 bot，另做共享查询入口 | 网页 / 共享表格放名单，全队能看、能自助改，链接发队群 | **推荐**，不受 iLink 限制，真正「人人可用、互不影响」 |
| 3. 每人各自绑一个 bot | 每个人自己扫码绑自己的 bot、跑自己的实例 | 不现实，每人要配服务器 |

**建议走方案 2**：bot 继续留给 owner 个人收每日提醒；另外做一个轻量网页（放名单 + 查询 + 自助增改），挂 GitHub Pages 免费（仓库已公开），把链接发到队群。
